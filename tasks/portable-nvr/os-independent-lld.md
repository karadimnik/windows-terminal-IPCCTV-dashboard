# OS-independent NVR: low-level implementation plan

Status: PROPOSAL for the Operator, 2026-10-17. Nothing here is built. Read `os-independent-hld.md` first (architecture,
technology choices, migration phases, decisions D2 to D18; D18, the unchanged archive layout, is superseded by D20: spool and day folders). The specification is `spec/inventory-recorder.md` (call it **IR**)
and `spec/inventory-supervisor.md` (call it **IS**); a reference like `IR 3.5` or `IS 2.2 G4` points into them, and every
constant below that is not marked UNVERIFIED was read from the PowerShell source by those inventories.

Conventions: package paths are under the Go module `holocron` (decision D2). Two hard rules govern everything (HLD section 0): **R1** one executable, `holocron`, for every action including install and uninstall; **R2** every action logged at a controllable level. All new code is standard
library except where section 8 names a pinned dependency. Every task ends with tests that can fail (a negative control) and a short
report; no stress, soak or endurance tests anywhere in this plan (the Operator's rule); "fault injection" means one clean
scenario run, not repetition.

## 1. Module layout

```

internal/clock/          Clock interface (UTC instants, monotonic intervals), DST helpers

internal/ffmpeg/         argument builder (golden-tested), child process, stderr drain and redaction
internal/relay/          MediaMTX config generators (relay, live), env scheme, API client, ready set
internal/status/         schema types, atomic writer, reader, liveness verdict, JSON Schema file
internal/supervise/      reconcile loop, backoff, stall watchdog, input choice, down alert, ordered stop
internal/host/           restart-in-place loop, stop classification, restart budget, alert 100/101/102/103
internal/alerts/         Event, dedupe/repeat rules, channels (log, webhook, push, desktop, eventlog/journald)
internal/secrets/        Provider interface + backends (keyring, encrypted file, env)
internal/osx/            per-OS: process lifetime, service install, dirs, disk free, root guards, perms, console events
internal/ctlapi/         local control endpoint (server) and client
internal/config/         holocron.config.json + cameras.json: types, defaults, validation, JSON Schema, atomic edit helpers (used by `cam` and `config` commands and by the web app)

tests/rig/               fake camera (ffmpeg lavfi), MediaMTX launcher, differential harness against PowerShell
```

## 2. Packages: contracts and rules

### 2.1 `clock`
`type Clock interface { Now() time.Time /* UTC */; Since(t time.Time) time.Duration /* monotonic where t has it */; Sleep... }`
with a real and a fake implementation. All persisted and compared instants are UTC; display forms keep the local offset (IS 1.1
timestamp format: RFC 3339 with 7 fractional digits and the offset in force, e.g. `2026-10-25T03:30:00.1234567+02:00`; `null` for
"never"). Intervals (heartbeat age, stall, backoff, alert repeat) use the monotonic reading so a +/- 3600 s wall-clock step cannot
fire or suppress them (IR section 11 risk 7; this is an improvement over PowerShell, which does not absorb the step).
Tests: the `dst` and `dstloop` tables from `tests/cam.tests.ps1` ported as a table test with the fake clock across 2026-10-25 and 2027-03-28 in the zone GTB Standard Time and Europe/Bucharest.

### 2.2 `archive`
- `SafeName(name) (string, error)` reproduces `Get-CamSafeName` byte for byte (IR 2): the output must equal existing folder names; known traps are leading `_`, `%`, trailing dot or space, Unicode whitespace, collisions (V3, V4, V5). A golden table is generated by running the PowerShell function over a corpus (Phase 0).
- `ParseSegment(file) (camera string, start time.Time, offset, ok bool)` and `FormatSegmentPattern(camera) string` for the strftime pattern with `%z`; the strict allowlist regex of `Test-CamSegmentName` (container-only, case-insensitive, folder parent equals the root).
- `Scan(dir) DirScan`: newest closed write, the open segment, counts and bytes. **The open segment** is the newest file matching the strict pattern whose modification time is within `SegmentSeconds + 60 s` of now; if two qualify the later name wins. This replaces NTFS creation time (HLD section 6; spike SP4).
- **Pruner as a pure planner**: `Plan(inputs) Decision` with inputs {files per camera with name, mtime, size; free bytes; rules (reserve, hysteresis, MaxRetentionDays, MaxAgePruneFraction); now; open-segment set; root verdict; marker verdict} and output {deletions (ordered), refusals with reason, `Blocked`, messages}. Gate order is the contract (IR 5, IR 11 risk 3): root problem, ownership marker, per-file allowlist (configured container only, strict regex, case-insensitive, parent equals root, no underscore folders, no symlinks), clock sanity (60 s future, 2250 s lag, inversion), age-rule circuit breaker (either share > MaxAgePruneFraction), strictly-older-than-newest rule, then the free-space watermark (trigger when free < reserve, stop at free >= reserve + hysteresis, global oldest-first by write time, free space re-read after each deletion in the executor). `Executor` performs deletions through an interface `FS` (Remove, Stat, FreeBytes) so tests use an in-memory FS and the real one is a thin wrapper. Alert 121 once per episode, re-armed only after a non-blocked run.
- Root guards (`RootProblem(path) string`): per-OS protected sets live in `osx` (IR section 10 item 6): Windows (Windows dir, Program Files, user profile, UNC share root, drive root), Linux/macOS (`/`, `/usr`, `/etc`, `/var`, `$HOME` and its parent, mount points, the program's own directory and its ancestors).
- Ownership marker: same claim rule as PowerShell (a root that holds only recorder files may be claimed; otherwise refuse). Marker file name and content copied from `Initialize-CamArchiveOwner` (IR 5).
Tests: the ten `prune*` checks become table tests (`prunematrix`, `pruneroots`, `pruneage`, `prunewatermark`, `pruneclock`, `pruneowner`, `prunebreaker`, `pruneblocked`, `pruneconfig`, `pruneloop`); plus the **differential harness** (section 6.3) over a generated corpus.

### 2.3 `ffmpeg`
- `BuildArgs(cfg, camera, input) []string` returns the exact vector in IR 1.1 (relay input and direct input; Matroska and fragmented-MP4 profiles; `-fflags +genpts+discardcorrupt`, `-segment_time`, `-segment_atclocktime 1`, `-reset_timestamps 1`, `-strftime 1`, the `%z` pattern, `-timeout`, `-rtsp_transport tcp`, `-map 0:v:0 -map 0:a:0?`, `-c copy`, audio handling, `-segment_format_options` placement). A **golden file per variant** pins it; the Phase 0 task generates the goldens from the PowerShell output so both implementations are held to one file. No shell quoting layer: arguments are an `[]string` (IR section 10 item 1).
- `Child`: starts ffmpeg through `osx` (own process group or job member), drains stderr with a 2 s final drain, redacts every line (`scheme://user:pass@` becomes `scheme://***:***@`, and registered secrets), tracks `StartedAt`, exit code, last error text `ffmpeg exited with code N after Ns`, and runs `RemoveEmptySegment` after every exit (a zero-length last file after a crash).
- Direct-input URLs carry the camera credential, which is todo [90]. The Go design removes the cause: the recorder reads only the relay path (no credential) by default; the direct path exists only as the documented fallback when the relay is down and passes the URL through the process environment of a wrapper or an input file, never the command line. Spike SP1b checks that ffmpeg accepts the URL from a `-protocol_whitelist`/`-f concat`-style input file or stdin; if not, the direct path is disabled by default and documented.

### 2.4 `supervise`
One reconcile goroutine, one heartbeat goroutine, and one waiter goroutine per child. The heartbeat is **independent of blocking work** (IS 1.1: today a relay restart blocks the loop for up to 20 s and can make the heartbeat look stale). Constants and rules, all from IR 3 and IS 2:

- Reconcile every `ReconcileSeconds` (5 s): re-read `cameras.json`; a child exists only for cameras with `Record` exactly `true` (JSON boolean; a string `"false"` is rejected, IR section 10 item 9) and a usable safe name; an IP or Quality change recreates the entry (and loses its restart counters, V12, kept as documented behaviour).
- **Backoff** per child: starts at 0; on exit the next delay is 3, 6, 12, 24, 48, 60, 60 s; reset to 3 only when the run lasted at least `HealthyResetSeconds` (300 s), evaluated at exit time; every exit counts (even code 0); a failed start backs off but is not counted as a restart (IR 3.5). `RestartsLastHour` is a ring of timestamps, not an unbounded list (IR section 10 item 11).
- **Stall watchdog**: a child is stalled when `now - max(StartedAt, newest closed write, creation of the open segment)` exceeds `StallFactor x SegmentSeconds` (2.5 x 900 = 2250 s); "creation of the open segment" is the first-seen time of the open file recorded by the scanner (not the filesystem birth time).
- **Input choice per start** from ONE shared ready-set per cycle (IR 11 risk 8): hold a camera's start while the relay is younger than `RelayReadyWaitSeconds` (15 s) and the path is not ready; stagger starts by `StartStaggerMs` (300 ms, non-blocking schedule); a live child on the direct input is moved to the relay without counting a restart once its path is ready; "denied" (wrong login) counts as ready; never probe per camera in a batch.
- **Down alert 110**: limit = `max(CameraDownAlertMinutes x 60, SegmentSeconds + StatusIntervalSeconds + 30)` seconds of no file progress, measured from `max(supervisor start, newest closed write, open-segment first-seen)`, repeating every `CameraDownRepeatHours` (12). Known latent issue V6: a camera enabled after the supervisor has run longer than the limit alerts at once because the floor is the supervisor start; the Go version uses `max(..., the time the camera's child first started)` as the floor and a conformance test documents the difference.
- **Ordered stop**: stop request received (control API, or the stop-request file as fallback) then cameras (hard kill, as today), then the live MediaMTX, then the relay; wait; write the final document `State=stopped` with `StopKind=requested`; remove the request; exit 0. A signal (interrupt, terminate) produces `interrupted`; a recovered panic or fault produces `unexpected` with `LastUnexpectedStop` (IS 2.2 G6).
- Pruner scheduling: every `PruneIntervalSeconds` (300 s) and at start; never on the heartbeat goroutine.

### 2.5 `status`
Go structs mirror IS section 1 exactly (top-level fields, `Disk`, `Prune`, `Restreamer`, `Live`, `Events`, `Cameras[]` with its 20 fields), serialised with indented JSON, UTF-8 without BOM. `Schema` stays `1` for compatibility with the PowerShell producer and the current `camui`; a new field is added only as optional. The draft JSON Schema at the end of IS section 1 becomes `internal/status/status.schema.json` after Phase 0 validates it against real documents from both producers.
- **Single writer**: the supervisor. Patches of today (window-close, unexpected stop, record toggle) become supervisor methods called through the control API or by the host over the same API; if the supervisor is dead the host writes the unexpected-stop document itself under the lock file (the only second writer, and only when no supervisor holds the lock).
- Atomic write: temp file in the same directory, flush, rename over. Windows rename over a file a reader holds open must be proven (spike SP6); readers open with share-delete where available and retry 5 x 80 ms as today.
- **Liveness verdict `Verdict(snapshot, now) (running bool, reason string)`**: fresh heartbeat (age <= max(3 x StatusIntervalSeconds, 15 s)) AND the recorded pid alive with the recorded start time (IS 2.2; `ui/supervisor.go` already mirrors this and is replaced by this package).
- `LastUnexpectedStop` is carried across a supervisor restart and re-emitted verbatim (the web app dismisses it by comparing the `At` string byte for byte, IS risk 3). `LastWindowClose` is carried too (intent of todo [78]; the PowerShell code drops it, finding F1): conformance test C-F1.
- Redaction: the whole serialised text passes the redactor before writing, and the web app keeps its own second scrub (IS risk 9).

### 2.6 `relay`
Port of `Get-CamRelayConfigText` and `Get-CamLiveConfigText`: the MediaMTX template, per-camera source via environment `MTX_PATHS_<NAME>_SOURCE` (name = lowercase alphanumeric of the camera name, collision rule from IR/IS 4), login block (`authInternalUsers`) with the product's API credential kept in an owner-only file, `webrtc*` keys for the live instance (loopback `webrtcAddress`, `webrtcLocalUDPAddress`, `webrtcAdditionalHosts` from `LiveAdvertiseHosts`, no origins), the live secret file (32 random bytes hex, owner-only, config holds only the SHA-256). Generated text for the default configuration is **byte-identical** to the PowerShell output (golden test; the Live-off case equals master's, the `livecfg` rule). The API client reads the ready set once per cycle and treats a 401 as "denied", not "down". MediaMTX is started from a local working directory (never a UNC path), as learned in Stage 1A.

### 2.7 `alerts`
`Event{ID, Severity, Title, Message, At, Key}`; ids and triggers from IR 6 (100 supervisor stopped unexpectedly, 101 restarted, 102 restart budget exhausted, 103 window closed, 110 camera down, 120 pruning disabled because the root is unsafe, 121 pruning blocked with the disk under the reserve, 122 the age-rule circuit breaker held a run, 130 relay API refused the login; 101 and 102 have no proving check today). Dedupe and repeat rules are per id exactly as listed in IR 6. Channels implement `Send(Event) error` and never block the caller (bounded queue, drop-oldest, one notice per episode): `log` (always on), `webhook` (JSON POST), `push` (ntfy-style HTTP), `desktop` (Windows toast through the existing mechanism, `notify-send`, `osascript`), `eventlog` (Windows Application log, source prefix `IPCCTV: `) and `journald`/syslog. A phone-reachable channel closes gap L7.

### 2.8 `secrets`
`Provider{ Get(name) (string, error); Put(name, value string) error; Delete(name) error }` with backends selected by `secrets.backend` (`auto|keyring|file|env`). `file`: AES-256-GCM, key from `NVR_SECRET_KEY` or an owner-only key file; `keyring`: one pinned library, evaluated in spike SP5 (headless Linux has no Secret Service); `env`: for containers. Camera credentials are read once at start and handed to MediaMTX through its environment; they are never written to a config file or a command line. A one-time importer converts `camera_creds.xml` (DPAPI) on Windows when the Operator asks, reading it through PowerShell's own `Import-Clixml` in a short child process, never by us parsing the file.

### 2.9 `osx` (build tags; one file per OS per capability)
```go
type Platform interface {
    // lifetime
    NewProcessScope(name string) (Scope, error)   // Windows job (kill on close), Linux group + Pdeathsig, macOS group
    Start(scope Scope, cmd *exec.Cmd) (Proc, error)
    Registry() ProcRegistry                       // pid + start time + image path, persisted in _state/children.json
    // environment
    Dirs() Dirs                                   // config, state, logs, auth, tls defaults
    DiskFree(path string) (uint64, error)
    RootProblem(path string) string               // protected-path sets
    SetOwnerOnly(path string) error               // 0600/0700 or owner-only ACL
    // console and service
    OnConsoleClose(func(Reason))                  // terminal closed / logoff / shutdown -> graceful stop with StopKind window-closed
    Service() ServiceManager                      // Install/Uninstall/Start/Stop/Status for task, service, systemd, launchd
    NotifyDesktop(title, msg string) error
}
```
Windows uses `golang.org/x/sys/windows` for job objects (`CreateJobObject`, `SetInformationJobObject` with kill-on-job-close, `AssignProcessToJobObject`; the handle is kept for the supervisor's life and is not inheritable); Linux sets `SysProcAttr{Pdeathsig, Setpgid}` and keeps the starting goroutine locked to its OS thread; macOS uses a process group and the registry reap (spike SP3 states what is and is not guaranteed). The registry reap on every OS: at start, for each entry verify pid alive, same start time and same image path, then stop it; never kill by image name alone.

### 2.10 `host`
`Run(budget)` starts the supervisor as a child process, waits, and classifies the stop from RECORDED state (the stop-request file, the persisted `StopKind`, exit code 20), never from the exit code alone (IS 2.3). Rules (IS 2.2 G4): restart in place after 5 s, at most 5 restarts in 30 minutes, alert 100 on an unexpected stop and 101 on restart, 102 and stay down when the budget is spent; never restart `requested`, `interrupted`, `window-closed` or exit 20; wait up to 20 s for the previous supervisor's lock before restarting. In attached mode `OnConsoleClose` stops the supervisor in order and records `window-closed` with alert 103 (one alert; an orderly stop raises none, G3); in service mode the OS manager's stop is `requested`.

### 2.11 `ctlapi` and the `camui` Controller
A loopback HTTP endpoint inside the supervisor (random port written to `_state/ctl.addr`, secret in an owner-only `_state/ctl.secret`, constant-time compare; no other listener): `GET /v1/state`, `POST /v1/stop`, `POST /v1/reload`, `POST /v1/cameras/{name}/record`, `POST /v1/live/enable|disable`. One state-changing action at a time (409 otherwise; G14, with a test). `camui` gets `type Controller interface { Status() (State, error); Start(scope) ...; Stop(scope) ...; SetRecord(name, bool) ... }` with two implementations: `PowerShellController` (today's `runPowerShell`, `schtasks` query; kept for the PowerShell system) and `APIController` (new). The camui binary chooses by what it finds in `_state` (a live `ctl.addr` means the Go supervisor). Start is the OS service manager's job; `holocron up` is what it runs.

### 2.12 The command tree (rule R1: one executable for everything)

Every command is `holocron <noun> <verb>` or a top-level verb. Each is an **Action** registered in `internal/cli` (section 2.13), is
callable from the command line, from the web app and through the control API with the same handler, and logs through the same
contract. The mapping column shows what it replaces.

| Command | Does | Replaces |
|---|---|---|
| `holocron up [--detach] [--only host\|web]` | Start everything in the right order (host, supervisor, relay, live relay, web). Attached by default: closing the terminal stops everything; `--detach` backgrounds it; the autostart entry runs this | `cam.ps1 -Start`, `-Nvr`, `camui.exe` |
| `holocron down` | Stop everything in order and prove it by counting roles before and after; exit 1 if anything survives; never kills by name alone | `cam.ps1 -Stop` |
| `holocron restart [--only ...]` | `down` then `up` for the chosen scope | - |
| `holocron status [--json]` | Roles, pids, camera states, disk, live view, web, autostart state; same exit codes | `cam.ps1 -Status` |
| `holocron cam list\|show\|add\|remove\|set\|enable\|disable\|test` | Edit `cameras.json` with validation and atomic write, hot reload by the supervisor, `test` probes a camera through the relay or directly | `cam.recorder.ps1 -Enable/-Disable`, hand edits, the Settings screen |
| `holocron config get\|set\|unset\|validate\|show` | Read and change `holocron.config.json` through an allow-list with validation (retention, reserve, segment length, live view, log levels) | hand edits, `PUT /api/config` |
| `holocron live enable\|disable\|status` | Switch live view and its LAN media address | config keys |
| `holocron web [--listen ...] [--tls-listen ...]` | Run only the web role (for diagnostics); normally started by `up` | `camui.exe` |
| `holocron open [camera]` | Open the default browser on the Live grid, or one camera | `mpv` grid launch |
| `holocron user add\|remove\|passwd\|list\|unlock` | Manage login users (roles later) | `camui -set-password`, `-unlock` |
| `holocron tls ca\|print\|rotate` | Local certificate authority tools | `camui -print-ca` |
| `holocron secret set\|delete\|import\|list` | Camera credentials in the secret store (list shows names only, never values) | `camera_creds.xml` setup prompt |
| `holocron install [--mode logon\|service\|systemd\|launchd] [--dry-run]` | Create the autostart entry for this OS and verify it; creates ONLY holocron's own entries and never touches the PowerShell system's tasks | `cam.ps1 -Install` |
| `holocron uninstall [--dry-run]` | Remove exactly what `install` created | `cam.ps1 -Uninstall` |
| `holocron autostart enable\|disable\|status` | Reversible on/off switch for the entry without removing it | - |
| `holocron prune [--dry-run]` | Show or run the pruner's decision now, using the same planner | - |
| `holocron archive stats` | Disk, retention, per-camera size and age | `Disk` section of `-Status` |
| `holocron logs [-f] [--component c] [--level l] [--since t] [--action a]` | Read, filter and follow the logs, including the audit stream | opening log files by hand |
| `holocron log level <component\|all> <level>` | Change a level at run time through the control API (persisted if `--save`) | - |
| `holocron alert test [channel]` | Send a test alert through a channel | - |
| `holocron doctor` | ffmpeg and MediaMTX found and versioned, ports free, directories writable, clock sane, archive root verdict, secret backend works, autostart state | `-SelfTest` |
| `holocron version` | Build and spec versions | - |

Exit codes keep their meaning: 0 ok, 1 failure (including "NOT RECORDING" and a stop that left survivors), 20 another supervisor holds
the archive, 21 configuration fault. `--json` on read commands for scripting. There is no command that requires elevation except
`install`/`uninstall` in `--mode service`, which says so before it asks.

### 2.13 The logging contract (rule R2)

Package `logx`, built on `log/slog`.

**Levels.** `ERROR` an action failed or an invariant broke; `WARN` degraded, retried, refused or throttled; `INFO` every state-changing
action and every lifecycle event; `DEBUG` decisions and their inputs; `TRACE` raw detail below DEBUG. Default INFO. Meaning by example:

| Level | Examples |
|---|---|
| ERROR | child exits abnormally with no restart budget; prune blocked; relay refused the login; config write failed; any command that returns non-zero |
| WARN | a restart with backoff; stall detected; direct input used because the relay is not ready; login failure or lockout; a guard refusal; a request throttled |
| INFO | `up`, `down`, `install`; child started or stopped with pid and reason; camera added, removed, enabled, disabled; config changed (key, old and new value, secrets masked); user added, login ok, logout; segment deleted by the pruner (file, bytes, reason); alert sent; TLS certificate renewed |
| DEBUG | backoff computation; relay-or-direct choice and the ready set; directory scan results; prune plan inputs and gate results; control-API and HTTP request lines; MediaMTX API calls |
| TRACE | ffmpeg stderr lines; raw status documents; per-tick scheduler decisions |

**Fields on every record:** `time` (RFC 3339 with offset), `level`, `component` (`cli`, `host`, `supervisor`, `ffmpeg:<camera>`, `relay`, `live`, `prune`, `web`, `auth`, `ctlapi`, `alerts`, `install`), `msg`, and for actions: `action`
(`noun.verb`, for example `camera.add`), `actor` (`cli:<os user>`, `web:<username>`, `host`, `supervisor`, `system`), `target`, `result`
(`ok`, `fail`, `refused`), `duration_ms`, `err`, `action_id` (one id per invocation, carried from the CLI through the control API into the
supervisor so one action reads as one thread across processes), `pid`.

**Control.** Configuration `logging.level` (default) and `logging.levels` (a map component to level); the environment variable
`HOLOCRON_LOG=debug` or `HOLOCRON_LOG=supervisor=debug,web=info` overrides it; `holocron log level ...` changes it live through the
control API; the CLI flags `-v` (DEBUG) and `-vv` (TRACE) set the level for that invocation and mirror its records to stderr.
**Destinations:** `<root>/_logs/holocron.log` (all components, text by default, JSON by option), one file per camera for ffmpeg output as
today, `<root>/_logs/audit.log` for security-relevant actions (login, user and certificate changes, camera and config changes, install,
uninstall, down) kept longer, stderr in attached mode, and the OS event log or journald where the channel is enabled.
**Rotation and safety:** the PowerShell rules carry over (IR 8): rotate at the size limit before append with one `.1` generation, a failed
rotation or append never fails the caller and produces one notice per episode, repeated lines collapse on a digit-stripped shape.
**Redaction** is a handler wrapper below every level: URLs with credentials, registered secrets, passwords, tokens, hashes and cookies
never reach any sink, including at TRACE; a test enables TRACE and scans every sink with a positive control.

**The action contract (what makes "every action" enforceable).** Each command, control-API handler and web handler is registered as an
`Action{Name, Component, Mutating bool, Handler}` in `internal/cli`; the runner, not the handler, writes `action.begin` (DEBUG) and the result
record (INFO for success of a mutating action, DEBUG for read-only success, WARN for refused, ERROR for failure) with the fields above, so a
handler cannot forget. Tests: (1) a registry test fails if any exposed command or route is not an Action (the same pattern as the web app's
route-classification test); (2) each Action is run against fakes and must leave exactly one begin and one result record with the required
fields, and a failing run must leave an ERROR or WARN record; (3) a level test proves a component override and a run-time change take effect
without a restart; (4) the TRACE leak scan above; (5) the audit stream receives every Mutating action.

## 3. Algorithms (pseudocode, normative where marked)

```
supervisor.Run():                                        # IS 2, IR 3
  lock := acquireExclusive(_state/supervisor.lock)  or exit 20            # S1; heartbeat check kept as second signal
  reap(registry)                                                          # provable orphans of a dead predecessor
  start heartbeat goroutine (status every StatusInterval, never blocked by relay/ffmpeg work)
  start relay (and live if enabled) ; publish ready set each cycle
  loop every ReconcileSeconds, until stop:
     cams := readCameras()                      # keep previous list on error
     for each cam with Record==true: ensure child (create entry; start if delay elapsed and input chosen)
     for each child: if exited -> account (RestartCount, backoff, LastError); removeEmptySegment
                     if stalled (see 2.4) -> hard kill, reason "stalled"
                     if direct and path ready -> kill, restart on relay, no restart counted
     if pruneDue: planner -> executor (never on the heartbeat goroutine)
     down alert per camera (limit and floor in 2.4)
  on stop: ordered stop (cameras, live, relay), final status, unlock
```
```
backoff(entry, ranFor):  if ranFor >= HealthyReset { next = 3 } else if next == 0 { next = 3 } else { next = min(next*2, 60) }
liveness(snapshot, now): ageOK := now-UpdatedAt <= max(3*StatusInterval, 15s);  pidOK := alive(pid) && startTime(pid) == recorded; return ageOK && pidOK
prunePlan(...):          see 2.2, gates in order; each refusal is a returned reason, never a partial delete
```

## 5. CLI-visible and web-visible compatibility rules

## 6. Test architecture

1. **Golden files** (Phase 0): ffmpeg vectors (every variant), the live and relay MediaMTX configs, a real `status.json` from each producer, the camera safe-name corpus, the DST table.
2. **Table tests** in Go for every rule above, each with a negative control, ported from the named PowerShell checks (IS section 7 lists all 58 checks with a suggested Go counterpart; 48 run by default, 10 are opt-in).
3. **Differential harness** (`tests/rig`): generate synthetic archive trees (names, mtimes, sizes, some foreign files, symlinks, underscore folders, clock-skewed files), run the PowerShell pruner (dry run, through the test library) and the Go planner, compare the ordered delete lists and refusal reasons. Feasibility is spike SP7; if the PowerShell pruner cannot run dry, the comparison uses recorded decisions from the existing check fixtures.
4. **Conformance suite** for `status.json`: validates documents from both producers against the Schema; the F1 and V6 differences are explicit expected-failure items on the PowerShell side.
5. **Fake-camera integration rig**: ffmpeg `lavfi` publisher into a MediaMTX path (exists in the PowerShell harness; reimplemented in Go test helpers on random ports with local working directories), used for: a recording scenario across two segment boundaries, camera drop and return, relay restart, supervisor kill (children gone, orphan registry), ordered stop (verified), single-instance lock (two starts at once, one wins), window/console close in attached mode.
6. **Cross-OS CI**: GitHub Actions matrix `windows-latest`, `ubuntu-latest` (and `macos-latest` if free) running unit, golden and rig tests; ffmpeg from the runner's package manager, MediaMTX downloaded at a pinned version; runs when the project has its own repository (HLD decision D16). Until then the same suite runs on this PC and in the Ubuntu WSL.
7. **What is not tested automatically**: real cameras, real sleep and resume, a physical NIC, phones. Those stay Operator-run checks with written steps.

## 11. Decisions taken from the spike results (2026-10-17)

Source: `spikes/holocron-spikes-1.md` (SP1, SP1b, SP4, SP6, SP7). These amend the sections named in the left column.

| Amends | Decision | Evidence |
|---|---|---|
| 2.3 `ffmpeg` | **Minimum ffmpeg 5.0**, checked at start and by `holocron doctor`; below that refuse with a clear message. The `-timeout` option (microseconds) exists only from 5.0; on 4.2.x the same flag turns the RTSP demuxer into a server and fails at once, and 4.x's `-stimeout` is rejected by 8.x | SP1 (V13) |
| 2.3 `ffmpeg` | **Remove `TZ` from the ffmpeg child's environment on Windows** (the Windows build honours POSIX-style `TZ` but produces a wrong offset silently for IANA names); leave it inherited on Linux, where ffmpeg honours it | SP1 (V8) |
| 2.3 `ffmpeg`, IR U2 | `-segment_atclocktime` cuts on multiples of N seconds counted from LOCAL midnight (for 7 s it is neither UTC nor epoch multiples); names and `%z` are identical on Windows and Linux; ffmpeg writes nothing to stdout in segment mode | SP1 (U2, U7) |
| 2.3 direct input (todo [90]) | Relay-only stays the default. The direct-input fallback may use an **ffconcat list file** (`ffconcat version 1.0`, `file 'rtsp://...'`, `option rtsp_transport tcp`, `option timeout N`; `-f concat -safe 0 -protocol_whitelist file,rtsp,tcp,rtp,udp -i list`): the password is absent from the process command line on Windows and Linux. The list file is created owner-only and deleted after the child exits; the redactor stays on the stderr path because ffmpeg prints the URL in errors. Not working: `-/i` file, environment, `.netrc`, stdin | SP1b |
| 2.2 `Scan` | **The open segment is ordered by mtime with name as the tie-break** (name order is wrong across a DST fall-back). `Scan` returns `Newest` (always protected by the pruner) and `Recent` (mtime within `SegmentSeconds + 60 s`, used only by the stall watchdog and the down alert). A future mtime counts as recent and raises a clock anomaly flag. NTFS directory size and mtime tracked `os.Stat` exactly, so there is no port of `Get-CamLiveFileLength` | SP4 |
| 2.2 names | Extension and pattern matching is **case-insensitive on Windows, case-sensitive on Linux and macOS** (platform flag, tested both ways) | SP4 |
| 2.5 `status` | **Reader:** `CreateFile` with `FILE_SHARE_READ|WRITE|DELETE`, read fully, close. **Writer:** temp file, flush, then a rename with POSIX semantics (`SetFileInformationByHandle`, `FileRenameInfoEx`, replace-if-exists and POSIX flags), falling back to `os.Rename` on errors 87 and 50 (the `\\wsl.localhost` 9P case); never `ReplaceFileW`. A failed replace skips the cycle and never blocks. The web app's own status read gets the same share-delete open, otherwise it blocks the Go writer | SP6 |
| 6 item 3 differential harness | Confirmed workable with new files only: `Invoke-CamPrune -DryRun` over a sandbox tree, decisions captured from its return hashtable, log lines and a file-manifest diff. ### 11.1 Decisions from spikes SP2 and SP3 (2026-10-20), `spikes/holocron-spikes-2.md`

| Amends | Decision | Evidence |
|---|---|---|
| 2.9, 2.10 host | **No keeper process.** In attached mode an in-process console handler is enough: Go maps `CTRL_CLOSE_EVENT` to SIGTERM, it arrives 6 to 66 ms after the close and the process then has **5.04 s** before Windows ends it (cleanup ran 2 ms after the signal). Same in Windows Terminal and conhost | SP2 |
| 2.10 host | **Abrupt console-host death sends no event** (a killed pty host or conhost left the process and its children running 15 to 25 s or more): the supervisor runs a console probe at 4 Hz (`GetConsoleProcessList` returns 0, `GetConsoleMode` fails, `GetConsoleWindow` returns 0; detected within 0.5 to 0.8 s) and treats it as a window close (`StopKind=window-closed`, alert 103) | SP2 |
| 2.9 children | Each child gets its OWN hidden console (`CREATE_NO_WINDOW`): a child sharing the supervisor's console is killed by the close event with no ordered stop | SP2 |
| 2.9 Windows | First create an unnamed, non-inheritable job with kill-on-close and NEVER breakaway-OK (grandchildren escaped when breakaway was allowed). Start every child with `syscall.CreateProcess` and `CREATE_SUSPENDED | CREATE_NO_WINDOW`, assign it to the job, then resume; a failed assignment is fatal for that child. The assign-after-start gap lets grandchildren escape (3 of 3 with a 300 ms gap); `CREATE_SUSPENDED` or the job-list attribute closes it. Nested jobs work. Hard kill of the supervisor leaves 0 survivors within about 0.1 s | SP3 |
| 2.9 Linux | `Setpgid` plus `Pdeathsig: SIGKILL`, with ONE dedicated goroutine that calls `runtime.LockOSThread()`, creates every child and never returns until shutdown (a starter that returns takes all children down within 1 ms while the supervisor lives). Grandchildren are not covered by `Pdeathsig` (3 of 3 survived); the orderly stop kills the group: `kill(-pgid, SIGTERM)`, a grace period, then `SIGKILL` | SP3 |
| 2.9 macOS | No kernel guarantee: `Setpgid`, the registry reap and the stdin-pipe watcher (killed all children within about 50 ms of a hard kill in the Linux test of the technique). Documented limit; launchd behaviour unverified | SP3 |
| 2.9 registry | `_state/children.json` (pid, start-time token, image path, group id on Unix) written atomically after each start; at supervisor start, before spawning, verify alive AND same start time AND same image (case-insensitive on Windows) and stop only provable orphans (3 of 3 reaped on both OSes; a PID-reuse decoy survived) | SP3 |
